# SecNote 1.2 — Android-приложение с локальным шифрованием

Проект собирается онлайн в GitHub Actions. Android Studio и Android SDK на компьютере не нужны.

## Изменения версии 1.2

- Кнопка `+` открывает выбор типа записи: **«Обычная заметка»** или **«Список»**.
- Обычная заметка содержит заголовок и единое текстовое поле. Блок чек-листа в ней больше не отображается.
- Список — отдельный тип записи. В нём каждый пункт создаётся отдельной строкой с собственным чекбоксом. Кнопка **«Добавить строку»** добавляет новую строку с галочкой; строки можно отмечать и удалять.
- Старые записи версии 1.1, в которых были пункты чек-листа, при чтении автоматически распознаются как списки. Остальные записи остаются обычными заметками.
- Раздел файлового хранилища показывает изображения плитками в галерее, а документы и остальные файлы — отдельным списком ниже.
- Изображение можно открыть в увеличенном просмотре, экспортировать или удалить. Файловый предпросмотр создаётся из зашифрованных данных во временном приватном файле, который удаляется после декодирования.
- Удалена фраза о необходимости/ненужности доступа к интернету из интерфейса.

## Основные параметры

- Название: **SecNote**.
- Package / Application ID: **`infernics.notes`**.
- Версия: **1.2** (versionCode 3).
- Android 8.0 (API 26) и выше.
- Основной пароль; ключ выводится через PBKDF2-HMAC-SHA256 (250 000 итераций, случайная соль).
- Шифрование заметок и файлов: AES-256-GCM.
- Автоматическая блокировка при уходе приложения в фон.
- Опциональный вход по сильной биометрии Android через `BiometricPrompt` и Android Keystore. Основной пароль остаётся резервным способом доступа.
- Настройки с графитовой тёмной темой и нейтральной светлой темой.
- Отдельное файловое хранилище; импорт файлов не меняет сценарий работы с заметками.
- Для выбора файлов используется системный Android Storage Access Framework.
- Резервное копирование Android отключено (`allowBackup=false`).

## Формат хранения и совместимость

Каждая запись хранится отдельным AES-256-GCM зашифрованным JSON-файлом во внутреннем приватном каталоге приложения. В JSON указывается тип записи (`NOTE` или `LIST`). Пункты списка и статусы чекбоксов тоже находятся внутри зашифрованного JSON.

Для совместимости с версией 1.1 поле `kind` необязательно при чтении: если старый файл не содержит `kind`, но содержит непустой массив `checklist`, запись распознаётся как `LIST`. В противном случае она распознаётся как `NOTE`. Таким образом, прежние заметки и старые чек-листы не должны исчезнуть при обновлении на 1.2.

Изображения и другие файлы хранятся отдельно от заметок в каталоге `file_vault`. Каждый файл зашифрован потоковым форматом AES-GCM с проверкой целостности блоков и завершающего блока. Метаданные также зашифрованы. Для предпросмотра изображение временно расшифровывается в приватный cache-файл, декодируется в уменьшенный bitmap, а временный файл удаляется.

**Важно:** при экспорте файл записывается в выбранное пользователем место в расшифрованном виде. После экспорта эта копия больше не защищена SecNote.

## Биометрия

При включении биометрии существующий ключ хранилища оборачивается ключом Android Keystore. Доступ к нему требует успешной сильной биометрической проверки через `BiometricPrompt.CryptoObject`. Пароль и открытый ключ не сохраняются в настройках. Если Android инвалидирует биометрический ключ (например, после изменения зарегистрированных биометрических данных), войдите основным паролем и включите биометрию заново.

## Онлайн-сборка APK

Workflow находится в `.github/workflows/build-apk.yml` и запускается при push в `main` или вручную из вкладки Actions. Он использует JDK 17, Android SDK 35 и Gradle 8.7, затем запускает unit-тесты и `assembleDebug`.

### Обновление существующего GitHub-репозитория с версии 1.1

1. Скачайте архив **SecNote-GitHub-Android-v1.2.zip** и распакуйте его на компьютере.
2. Откройте существующий GitHub-репозиторий, в котором сейчас лежит SecNote 1.1.
3. В репозитории откройте **Add file → Upload files**.
4. Перетащите содержимое папки `SecNote-Android` (не сам ZIP-файл). Подтвердите замену существующих файлов и добавление новых. Особенно важно обновить папку `app/src/main/java/infernics/notes/` и файл `app/build.gradle.kts`.
5. Не удаляйте `signing/secure-notes-debug.keystore`: он нужен для подписи обновления тем же ключом, что и предыдущая версия.
6. Если скрытая `.github` не загружается, её можно не загружать: в существующем репозитории workflow уже должен быть настроен. Не создавайте второй workflow с тем же назначением.
7. Нажмите **Commit changes** в ветку `main`. Существующий workflow запустится автоматически.
8. Откройте **Actions**, дождитесь зелёной галочки у самого последнего запуска. Откройте этот запуск → **Artifacts** → скачайте `app-debug.apk`.
9. Установите APK поверх SecNote 1.1. Package ID и debug-подпись сохранены, поэтому Android должен распознать его как обновление, а данные приложения останутся на месте.

### Если репозиторий новый

Распакуйте ZIP и загрузите содержимое папки `SecNote-Android` в корень нового репозитория. Если `.github` не загрузилась, создайте файл `.github/workflows/build-apk.yml` вручную и скопируйте в него содержимое workflow из архива. Затем сделайте Commit changes.

## Что проверить в версии 1.2

1. Нажмите `+`: должны появиться два варианта — «Обычная заметка» и «Список».
2. Создайте заметку: в ней должен быть только заголовок и текст, без секции чек-листа.
3. Создайте список: первая строка отображает чекбокс; нажмите «Добавить строку» для следующего пункта. Отметьте несколько пунктов, сохраните, закройте и откройте список повторно.
4. Создайте записи в обоих форматах. В списке записей у них должны быть разные метки «ЗАМЕТКА» и «СПИСОК».
5. Откройте файловое хранилище и добавьте несколько изображений и документов. Изображения должны располагаться плитками в разделе «Фотографии», документы — ниже, в разделе «Файлы и документы».
6. Проверьте открытие фотографии, экспорт и удаление.
7. Проверьте биометрию, пароль и автоматическую блокировку.

## Безопасность и подпись

- Репозиторий рекомендуется держать **Private**: архив содержит debug-keystore и его пароль для подписи личных тестовых сборок.
- Не удаляйте `signing/secure-notes-debug.keystore`, если хотите устанавливать обновления поверх предыдущей версии.
- Debug APK предназначен для личной установки и тестирования, не для Google Play.
- Потеря основного пароля может привести к безвозвратной потере данных. Не забудьте безопасно хранить пароль.
